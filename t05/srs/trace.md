# СРС 5. Трассировка рекурсивной функции

```csharp
static int F(int n)
{
    if (n <= 1) return 1;
    return n * F(n - 1);
}
```

Функция вычисляет факториал: F(n) = n! (для n ≥ 1).

## 1. Базовый случай и шаг рекурсии

- **Базовый случай:** `if (n <= 1) return 1;` — при `n ≤ 1` функция больше не вызывает саму себя и сразу возвращает `1`. Именно здесь рекурсия останавливается.
- **Шаг рекурсии:** `return n * F(n - 1);` — функция вызывает саму себя с аргументом на 1 меньше и умножает результат на `n`. С каждым вызовом `n` уменьшается, поэтому рано или поздно мы приходим к базовому случаю.

## 2. Ручная трассировка F(4)

### Спуск вниз по стеку (вызовы)

Каждый вызов кладётся в стек и ждёт, пока вернётся следующий:

| Вызов | Глубина | Что делает                       |
|-------|---------|----------------------------------|
| F(4)  | 1       | 4 > 1 → вызывает F(3), ждёт      |
| F(3)  | 2       | 3 > 1 → вызывает F(2), ждёт      |
| F(2)  | 3       | 2 > 1 → вызывает F(1), ждёт      |
| F(1)  | 4       | 1 ≤ 1 → базовый случай           |

Состояние стека в самой глубокой точке (сверху — последний вызов):

```
| F(1) |  ← вершина стека, глубина 4
| F(2) |
| F(3) |
| F(4) |  ← первый вызов, глубина 1
```

### Подъём вверх (возвращаемые значения)

Вызовы снимаются со стека в обратном порядке:

| Вызов | Глубина | Вычисление     | Возвращает |
|-------|---------|----------------|------------|
| F(1)  | 4       | базовый случай | 1          |
| F(2)  | 3       | 2 · F(1) = 2 · 1 | 2        |
| F(3)  | 2       | 3 · F(2) = 3 · 2 | 6        |
| F(4)  | 1       | 4 · F(3) = 4 · 6 | 24       |

### Итоговая таблица

| Вызов | Глубина | Возвращает |
|-------|---------|------------|
| F(4)  | 1       | 24         |
| F(3)  | 2       | 6          |
| F(2)  | 3       | 2          |
| F(1)  | 4       | 1          |

**Результат:** F(4) = 4 · 3 · 2 · 1 = **24** (= 4!). Максимальная глубина стека — 4.

## 3. Что будет при F(-1), если условие заменить на `n == 1`

```csharp
static int F(int n)
{
    if (n == 1) return 1;   // изменённое условие
    return n * F(n - 1);
}
```

Вызов `F(-1)`:

| Вызов  | Глубина | n == 1 ? |
|--------|---------|----------|
| F(-1)  | 1       | нет → F(-2) |
| F(-2)  | 2       | нет → F(-3) |
| F(-3)  | 3       | нет → F(-4) |
| …      | …       | нет → …     |

**Почему так происходит:** `n` начинается с `-1` и при каждом вызове только **уменьшается** (-1, -2, -3, …). Число никогда не станет равным `1`, поэтому базовый случай не срабатывает ни разу — рекурсия бесконечная.

**К какой ошибке это приведёт:** каждый вызов занимает место в стеке вызовов, а его размер ограничен (по умолчанию около 1 МБ на поток). Через несколько десятков тысяч вызовов стек заканчивается, и программа аварийно завершается с ошибкой **`StackOverflowException`** (переполнение стека). В .NET это исключение нельзя перехватить через `try/catch` — процесс просто падает с сообщением `Stack overflow`.

С исходным условием `n <= 1` такой проблемы нет: `F(-1)` сразу попадает в базовый случай (`-1 <= 1`) и возвращает `1`. Поэтому условие `n <= 1` надёжнее — оно защищает и от нуля, и от отрицательных чисел.
