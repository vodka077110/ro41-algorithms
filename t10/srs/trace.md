# СРС 10. Трассировка поиска и сортировок

## 1. Сортировка выбором, `a = {5, 2, 9, 1, 7}`

```csharp
for (int i = 0; i < n - 1; i++)
{
    int min = i;
    for (int j = i + 1; j < n; j++)
        if (a[j] < a[min]) min = j;      // одно сравнение
    (a[i], a[min]) = (a[min], a[i]);     // обмен
}
```

На каждом проходе ищем минимум в неотсортированной части `a[i..n-1]` и ставим его на место `i`.

| Проход i | Ищем среди      | Индекс минимума | Обмен        | Массив после обмена | Сравнений |
|----------|-----------------|-----------------|--------------|---------------------|-----------|
| 0        | {5, 2, 9, 1, 7} | 3 (значение 1)  | a[0] ↔ a[3]  | {**1**, 2, 9, 5, 7} | 4         |
| 1        | {2, 9, 5, 7}    | 1 (значение 2)  | на месте     | {1, **2**, 9, 5, 7} | 3         |
| 2        | {9, 5, 7}       | 3 (значение 5)  | a[2] ↔ a[3]  | {1, 2, **5**, 9, 7} | 2         |
| 3        | {9, 7}          | 4 (значение 7)  | a[3] ↔ a[4]  | {1, 2, 5, **7**, 9} | 1         |

После прохода 3 последний элемент (9) уже стоит на своём месте, поэтому проходов `n − 1 = 4`.

**Общее число сравнений:** 4 + 3 + 2 + 1 = **10** = n·(n − 1) / 2. Сортировка выбором всегда делает столько сравнений, даже если массив уже отсортирован.

**Результат:** `{1, 2, 5, 7, 9}`.

## 2. Сортировка вставками, `a = {4, 3, 2, 1}`

```csharp
for (int i = 1; i < n; i++)
{
    int key = a[i];
    int j = i - 1;
    while (j >= 0 && a[j] > key)   // сравнение
    {
        a[j + 1] = a[j];           // сдвиг вправо
        j--;
    }
    a[j + 1] = key;                // вставка
}
```

`key` — элемент, который вставляем в уже отсортированную левую часть. Все элементы больше `key` сдвигаются на одну позицию вправо.

| i | key | Какие элементы сдвинуты | Число сдвигов | Массив после вставки |
|---|-----|-------------------------|---------------|----------------------|
| 1 | 3   | 4                       | 1             | {**3**, 4, 2, 1}     |
| 2 | 2   | 4, 3                    | 2             | {**2**, 3, 4, 1}     |
| 3 | 1   | 4, 3, 2                 | 3             | {**1**, 2, 3, 4}     |

**Всего сдвигов:** 1 + 2 + 3 = **6**. Это худший случай — массив отсортирован в обратном порядке, и каждый новый `key` приходится сдвигать в самое начало.

**Отсортированный массив из 4 элементов**, например `{1, 2, 3, 4}`:

| i | key | Сравнение      | Сдвигов | Сравнений |
|---|-----|----------------|---------|-----------|
| 1 | 2   | 1 > 2 — нет    | 0       | 1         |
| 2 | 3   | 2 > 3 — нет    | 0       | 1         |
| 3 | 4   | 3 > 4 — нет    | 0       | 1         |

Алгоритм выполнит **3 сравнения** (n − 1) и ни одного сдвига: на каждом шаге первое же сравнение показывает, что `key` уже стоит на своём месте, и цикл `while` сразу заканчивается. Это лучший случай сортировки вставками — она работает за линейное время.

## 3. Бинарный поиск в `{1, 3, 5, 7, 9, 11, 13}`

```csharp
int lo = 0, hi = n - 1;
while (lo <= hi)
{
    int mid = (lo + hi) / 2;
    if (a[mid] == x) return mid;
    if (a[mid] < x) lo = mid + 1;   // искомое правее
    else            hi = mid - 1;   // искомое левее
}
return -1;
```

Индексы: `a[0]=1, a[1]=3, a[2]=5, a[3]=7, a[4]=9, a[5]=11, a[6]=13`.

### x = 7

| Шаг | lo | hi | mid | a[mid] | Решение                  |
|-----|----|----|-----|--------|--------------------------|
| 1   | 0  | 6  | 3   | 7      | 7 == 7 → **найдено**, return 3 |

Число 7 стоит ровно в середине, поэтому найдено за **1 шаг**. Ответ: индекс **3**.

### x = 6

| Шаг | lo | hi | mid | a[mid] | Решение                        |
|-----|----|----|-----|--------|--------------------------------|
| 1   | 0  | 6  | 3   | 7      | 7 > 6 → идём влево, hi = 2     |
| 2   | 0  | 2  | 1   | 3      | 3 < 6 → идём вправо, lo = 2    |
| 3   | 2  | 2  | 2   | 5      | 5 < 6 → идём вправо, lo = 3    |
| —   | 3  | 2  | —   | —      | lo > hi → цикл заканчивается   |

**Чем закончится поиск:** после 3 шагов `lo = 3`, `hi = 2`, то есть `lo > hi` — участок для поиска стал пустым. Числа 6 в массиве нет, метод возвращает **−1**.

Обратите внимание: `lo = 3` остановился как раз на месте, куда число 6 можно было бы вставить (между 5 и 7).

### LowerBound(6)

`LowerBound(x)` возвращает индекс **первого элемента, который ≥ x** (если такого нет — `n`).

```csharp
int lo = 0, hi = n;          // hi = n, а не n - 1
while (lo < hi)
{
    int mid = (lo + hi) / 2;
    if (a[mid] < x) lo = mid + 1;
    else            hi = mid;
}
return lo;
```

| Шаг | lo | hi | mid | a[mid] | Решение                      |
|-----|----|----|-----|--------|------------------------------|
| 1   | 0  | 7  | 3   | 7      | 7 ≥ 6 → hi = 3               |
| 2   | 0  | 3  | 1   | 3      | 3 < 6 → lo = 2               |
| 3   | 2  | 3  | 2   | 5      | 5 < 6 → lo = 3               |
| —   | 3  | 3  | —   | —      | lo == hi → return 3          |

**`LowerBound(6)` вернёт 3** — индекс числа 7, первого элемента, который не меньше 6. Именно на позицию 3 нужно вставить 6, чтобы массив остался отсортированным: `{1, 3, 5, 6, 7, 9, 11, 13}`.

Для сравнения: `LowerBound(7)` тоже вернёт 3, потому что 7 есть в массиве и стоит на индексе 3.
